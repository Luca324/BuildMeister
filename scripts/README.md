# Скрипты проекта

## compile-extensions.js

Автоматический скрипт компиляции всех расширений и темы перед сборкой приложения.

### Назначение

Этот скрипт решает проблему нестабильного попадания компонентов из расширений в production bundle. Он гарантирует, что:

1. Все расширения скомпилированы перед сборкой приложения
2. Папки `dist` очищаются перед компиляцией для чистоты сборки
3. Проверяется успешность компиляции каждого модуля

### Использование

#### Автоматический запуск

Скрипт автоматически запускается при выполнении `npm run build` через `prebuild` hook в `package.json`:

```bash
npm run build  # Автоматически скомпилирует расширения перед сборкой
```

#### Ручной запуск

Можно запустить скрипт вручную:

```bash
npm run compile:extensions
# или
node scripts/compile-extensions.js
```

### Что делает скрипт

1. **Компилирует тему** `themes/tech` (если существует)
2. **Компилирует все расширения** из папки `extensions/`:
   - Проверяет наличие `package.json` и скрипта `compile`
   - Очищает старую папку `dist`
   - Выполняет `npm run compile`
   - Проверяет, что `dist` создана и не пуста

### Обработка ошибок

- Если компиляция какого-либо модуля завершилась с ошибкой, скрипт остановится с кодом выхода 1
- Все ошибки выводятся в консоль с понятными сообщениями
- Успешные компиляции отмечаются зеленым цветом

### Зависимости

Скрипт использует только стандартные модули Node.js:
- `child_process` для выполнения команд
- `fs` для работы с файловой системой
- `path` для работы с путями

### Примечания

- Скрипт работает в Windows и Unix-подобных системах
- Порядок компиляции расширений детерминирован (сортировка по имени)
- Скрипт проверяет наличие скрипта `compile` в `package.json` перед компиляцией

## db-dump.sh

Скрипт для создания дампа базы данных PostgreSQL.

### Назначение

Создает резервную копию базы данных в формате PostgreSQL custom format (`.dump` файл) с временной меткой в имени файла.

### Использование

#### Docker режим (по умолчанию)

```bash
# Создать дамп в директории backups (по умолчанию)
./scripts/db-dump.sh

# Создать дамп в указанной директории
./scripts/db-dump.sh /app/backups
```

#### Локальный режим

```bash
# Создать дамп локально (загружает переменные из .env)
./scripts/db-dump.sh local
./scripts/db-dump.sh local /path/to/backups
```

### Что делает скрипт

1. **Определяет режим работы**: Docker (переменные из окружения) или Local (из `.env` файла)
2. **Проверяет наличие обязательных переменных**: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`
3. **Создает директорию для бэкапов** (если не существует)
4. **Генерирует имя файла** с временной меткой: `backup_YYYYMMDD_HHMMSS.dump`
5. **Создает дамп** используя `pg_dump` в формате custom с блоб-данными

### Формат файла дампа

Файлы создаются с именами вида: `backup_20240115_143022.dump`

### Требования

- PostgreSQL клиент (`pg_dump`) должен быть установлен
- Доступ к базе данных с указанными учетными данными
- В Docker режиме: переменные окружения должны быть загружены через `env_file` в docker-compose.yml
- В локальном режиме: файл `.env` должен существовать в корне проекта

## db-restore.sh

Скрипт для восстановления базы данных PostgreSQL из дампа.

### Назначение

Восстанавливает базу данных из файла дампа, созданного с помощью `db-dump.sh`. Поддерживает автоматический выбор новейшего бэкапа и работу в двух режимах: Docker и локальный.

### Использование

#### Docker режим (по умолчанию)

```bash
# Автоматически выбрать новейший бэкап из backups/
./scripts/db-restore.sh

# Восстановить из конкретного файла
./scripts/db-restore.sh /app/backups/backup_20240115_143022.dump
```

#### Локальный режим

```bash
# Автоматически выбрать новейший бэкап локально
./scripts/db-restore.sh local

# Восстановить из конкретного файла локально
./scripts/db-restore.sh local /path/to/backup.dump
./scripts/db-restore.sh --local /path/to/backup.dump
```

### Что делает скрипт

1. **Определяет режим работы**: Docker или Local
2. **Загружает переменные окружения**:
   - Docker режим: использует переменные из окружения контейнера
   - Local режим: загружает из `.env` файла в корне проекта
3. **Проверяет наличие обязательных переменных**: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`
4. **Определяет файл дампа**:
   - Если путь указан явно — использует его
   - Если путь не указан — автоматически находит новейший файл `backup_*.dump` в директории `backups/`
5. **Восстанавливает БД** используя `pg_restore` с опциями:
   - `-c` — очистка существующих объектов перед восстановлением
   - `-v` — подробный вывод процесса

### Автоматический выбор бэкапа

Если путь к файлу не указан, скрипт автоматически:
- Ищет файлы с паттерном `backup_*.dump` в директории `backups/`
- Сортирует их по времени модификации (новейший первый)
- Выбирает самый свежий файл
- Выводит сообщение о выбранном файле

### Требования

- PostgreSQL клиент (`pg_restore`) должен быть установлен
- Доступ к базе данных с указанными учетными данными
- В Docker режиме: переменные окружения должны быть загружены через `env_file` в docker-compose.yml
- В локальном режиме: файл `.env` должен существовать в корне проекта

### Обработка ошибок

- Проверка наличия всех обязательных переменных окружения
- Проверка существования файла дампа
- Проверка наличия директории `backups/` при автоматическом поиске
- Информативные сообщения об ошибках с указанием режима работы

### Примечания

- Скрипт использует формат custom PostgreSQL, созданный `pg_dump` с опцией `-F c`
- При восстановлении существующие объекты БД удаляются перед импортом (`-c`)
- В Docker режиме путь к директории `backups/` обычно `/app/backups`
- В локальном режиме путь к директории `backups/` — `PROJECT_ROOT/backups`

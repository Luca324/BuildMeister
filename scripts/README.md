# Скрипты экспорта и импорта данных EverShop

Этот набор скриптов позволяет экспортировать и импортировать данные из/в базу данных EverShop используя стандартные инструменты PostgreSQL.

## Требования

- PostgreSQL клиентские инструменты (`pg_dump`, `pg_restore`)
- Настроенный `.env` файл с параметрами подключения к БД

## Настройка подключения к БД

Создайте файл `.env` в корне проекта со следующими переменными:

```env
# Настройки подключения к базе данных
DB_HOST=localhost
DB_PORT=5433
DB_NAME=postgres
DB_USER=postgres
DB_PASSWORD=qwerty1234
DB_SSLMODE=disable
```

## Использование

### Экспорт данных (бэкап БД)

Для создания полного бэкапа базы данных:

```bash
npm run db:export
```

Или напрямую:
```bash
./scripts/db-dump.sh
```

Скрипт создаст дамп в формате PostgreSQL custom format в папке `./backups`:
- `backup_YYYYMMDD_HHMMSS.dump` - сжатый бинарный дамп БД

Для указания кастомной директории:
```bash
./scripts/db-dump.sh /path/to/backups
```

### Импорт данных (восстановление БД)

Для восстановления базы данных из дампа:

```bash
npm run db:import ./backups/backup_20241215_143022.dump
```

Или напрямую:
```bash
./scripts/db-restore.sh ./backups/backup_20241215_143022.dump
```

Скрипт:
- Очистит существующие объекты БД перед восстановлением
- Восстановит схему, данные, индексы и последовательности
- Сохранит все зависимости и ограничения

## Особенности

### Экспорт (pg_dump)
- ✅ Стандартный инструмент PostgreSQL - надежность гарантирована
- ✅ Бинарный формат с сжатием - быстрее и компактнее CSV
- ✅ Полный дамп: схема + данные + индексы + последовательности + триггеры
- ✅ Атомарность операций
- ✅ Автоматическая отметка времени в имени файла

### Импорт (pg_restore)
- ✅ Быстрое восстановление из бинарного формата
- ✅ Автоматическая очистка объектов перед восстановлением
- ✅ Восстановление всех зависимостей в правильном порядке
- ✅ Поддержка частичного восстановления (при необходимости)

## Примеры использования

### Экспорт из локальной БД
```bash
# Настройте .env для локальной БД
DB_HOST=localhost
DB_PORT=5433
DB_USER=postgres
DB_PASSWORD=mypassword

# Экспортируйте данные
npm run db:export
```

### Восстановление в Docker контейнер
```bash
# Настройте .env для Docker
DB_HOST=db
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=password

# Восстановите данные
npm run db:import ./backups/backup_20241215_143022.dump
```

### Экспорт с кастомной директорией
```bash
./scripts/db-dump.sh /custom/backup/path
```

## Формат дампа

Дампы создаются в формате **PostgreSQL Custom Format** (`.dump`):
- Сжатый бинарный формат
- Быстрый импорт/экспорт
- Поддержка всех типов данных PostgreSQL включая BLOB
- Возможность частичного восстановления

## Устранение неполадок

### Ошибка подключения к БД
Убедитесь, что:
- БД запущена и доступна
- Правильно настроены переменные окружения в `.env`
- У пользователя есть права на чтение/запись в БД
- PostgreSQL клиентские инструменты установлены (`pg_dump`, `pg_restore`)

### Ошибка "pg_dump: command not found"
Установите PostgreSQL клиентские инструменты:
- **Ubuntu/Debian**: `sudo apt-get install postgresql-client`
- **macOS**: `brew install postgresql`
- **Docker**: используйте образ с установленными инструментами

### Проблемы с правами доступа
Убедитесь, что:
- Пользователь БД имеет права на создание/удаление объектов
- Файловая система имеет права на запись в директорию бэкапов

### Проверка дампа
Для просмотра содержимого дампа без восстановления:
```bash
pg_restore -l backup_file.dump
```

## Поддержка

При возникновении проблем проверьте:
1. Логи выполнения скриптов
2. Настройки подключения к БД в `.env`
3. Права доступа к файлам и БД
4. Установлены ли PostgreSQL клиентские инструменты

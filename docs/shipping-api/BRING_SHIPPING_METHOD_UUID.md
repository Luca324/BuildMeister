# Настройка метода Bring (план «без патча»)

Чтобы при выборе доставки Bring заказ создавался без ошибки «Shipping method is required», в корзине в поле `shipping_method` сохраняется **UUID одной записи** из таблицы `shipping_method`, а полный JSON выбранного варианта — в `shipping_method_metadata`.

## Что нужно сделать вручную

### 1. Создать метод доставки «Bring» в админке

1. Зайди в **Админка → Checkout → Shipping** (зоны и методы доставки).
2. Выбери нужную **Shipping Zone** (или создай зону для Норвегии/нужной страны).
3. В этой зоне **добавь новый метод доставки**:
   - Название: например **Bring** (как будет отображаться в списке нативных методов; пользователи всё равно выбирают вариант в блоке Bring).
   - Тип расчёта: **Flat rate** с ценой **0** (реальная цена подставляется из выбранного варианта Bring).
   - Сохрани метод.
4. После сохранения открой этот метод ещё раз или посмотри в БД — скопируй его **UUID** (поле `uuid` в таблице `shipping_method`).

### 2. Указать UUID в настройках расширения

В настройках приложения хранится JSON настройки `shipping_api` (таблица `setting`, имя `shipping_api`). В этом JSON нужно задать UUID созданного метода:

```json
{
  "providers": {
    "bring": {
      "enabled": true,
      "api_key": "...",
      "api_uid": "...",
      "client_url": "...",
      "customer_number": "...",
      "shipping_method_uuid": "СЮДА_ВСТАВЬ_UUID_ИЗ_ШАГА_1"
    }
  }
}
```

Поле **`shipping_method_uuid`** обязательно для работы плана «без патча». Если его нет, при сохранении выбранного варианта Bring появится ошибка с текстом о том, что нужно создать метод в админке и указать его UUID.

### 3. Проверка

- Выбери вариант Bring на чекауте, перейди к оплате, оформи заказ — ответ должен быть 200, без «Shipping method is required».
- В заказе в БД: `shipping_method` = этот UUID, `shipping_method_metadata` = JSON с `provider`, `metadata.deliveryOptionId` и т.д.
- После оплаты процессор создаёт отправление в Bring по данным из `shipping_method_metadata`.

# Шаг 4: Создание UI компонентов

## Цель
Создать пользовательский интерфейс для выбора вариантов доставки на странице checkout с debounce логикой и обработкой ошибок.

---

## Архитектура UI

### Принцип работы

```
Checkout Page
    ↓
ShippingOptionsBlock Component
    ↓
Пользователь заполняет адрес
    ↓
Debounce (500-800ms)
    ↓
GraphQL Mutation: calculateShipping
    ↓
Отображение вариантов доставки
    ↓
Пользователь выбирает вариант
    ↓
Сохранение в cart.shipping_method
    ↓
Обновление итоговой стоимости
```

## ShippingOptionsBlock Component

### Назначение

Отдельный блок на странице checkout, который:
- Отображает форму ввода адреса доставки (или использует существующую)
- Показывает варианты доставки от всех активных провайдеров
- Позволяет выбрать вариант доставки
- Обновляет стоимость заказа при выборе

### Расположение на странице

Компонент должен отображаться на странице checkout после формы адреса доставки и перед формой оплаты.

### Логика работы компонента

#### 1. Инициализация

- Загрузить текущую корзину через GraphQL query
- Проверить, заполнен ли адрес доставки
- Если адрес заполнен - автоматически вызвать расчет доставки
- Если адрес не заполнен - показать форму ввода адреса

#### 2. Отслеживание изменений адреса

- Подписаться на изменения полей адреса:
  - `postcode`
  - `city`
  - `address_1`
  - `country`
  - `province`
- Использовать debounce для вызова API:
  - Задержка: 500-800 мс после последнего изменения
  - Проверка: все обязательные поля заполнены перед вызовом API

#### 3. Вызов API расчета

**Условия для вызова**:
- Все обязательные поля адреса заполнены
- Прошло 500-800 мс после последнего изменения
- Корзина содержит товары

**Процесс**:
1. Показать состояние загрузки (spinner или skeleton)
2. Вызвать GraphQL mutation `calculateShipping(cartId)`
3. Обработать ответ:
   - Успех: отобразить варианты доставки
   - Ошибка: показать сообщение об ошибке
   - Пустой результат: показать сообщение "Доставка недоступна"

#### 4. Отображение вариантов доставки

**Структура блока**:

```
┌─────────────────────────────────────────┐
│ Доступные варианты доставки:            │
├─────────────────────────────────────────┤
│ PostNord:                                │
│ ☐ Standard (5-7 дн) — 199 kr           │
│ ☐ Express (1-2 дн) — 399 kr            │
├─────────────────────────────────────────┤
│ Helthjem:                                │
│ ☐ Standard (2-3 дн) — 179 kr           │
├─────────────────────────────────────────┤
│ ❌ Bring временно недоступен            │
└─────────────────────────────────────────┘
```

**Группировка**:
- Варианты группируются по провайдеру
- Каждый провайдер имеет заголовок с названием
- Если провайдер недоступен - показать сообщение об ошибке

**Формат варианта**:
- Радио-кнопка для выбора
- Название варианта (например, "PostNord Standard")
- Срок доставки (если доступен)
- Цена
- Дополнительная информация (если есть)

#### 5. Выбор варианта

**При выборе варианта**:
1. Сохранить выбранный вариант в `cart.shipping_method` через GraphQL mutation
2. Обновить стоимость доставки в корзине
3. Обновить итоговую стоимость заказа
4. Визуально выделить выбранный вариант

**GraphQL mutation для сохранения**:
```graphql
mutation UpdateShippingMethod($cartId: ID!, $shippingMethod: JSON!) {
  updateCartShippingMethod(cartId: $cartId, shippingMethod: $shippingMethod) {
    cart {
      shippingFee {
        value
        text
      }
      grandTotal {
        value
        text
      }
    }
  }
}
```

#### 6. Обработка ошибок

**Типы ошибок и их отображение**:

1. **Все провайдеры недоступны**:
   ```
   ┌─────────────────────────────────────────┐
   │ ❌ Сервисы доставки временно            │
   │    недоступны. Пожалуйста,             │
   │    попробуйте позже.                   │
   └─────────────────────────────────────────┘
   ```

2. **Один провайдер недоступен**:
   ```
   ┌─────────────────────────────────────────┐
   │ ❌ PostNord временно недоступен         │
   ├─────────────────────────────────────────┤
   │ Helthjem:                                │
   │ ☐ Standard (2-3 дн) — 179 kr           │
   └─────────────────────────────────────────┘
   ```

3. **Адрес недоступен**:
   ```
   ┌─────────────────────────────────────────┐
   │ ❌ Доставка в этот адрес                 │
   │    недоступна                           │
   └─────────────────────────────────────────┘
   ```

4. **Ошибка сети**:
   ```
   ┌─────────────────────────────────────────┐
   │ ❌ Ошибка соединения.                   │
   │    Пожалуйста, попробуйте еще раз.     │
   │    [Повторить]                          │
   └─────────────────────────────────────────┘
   ```

#### 7. Состояния компонента

**Состояния**:
- `idle` - начальное состояние, адрес не заполнен
- `loading` - идет загрузка вариантов доставки
- `loaded` - варианты загружены и отображаются
- `error` - произошла ошибка
- `empty` - варианты недоступны для данного адреса

## Debounce логика

### Реализация

Использовать библиотеку `lodash.debounce` или собственную реализацию:

```typescript
// Пример реализации
const debouncedCalculateShipping = useMemo(
  () => debounce((address) => {
    if (isAddressComplete(address)) {
      calculateShipping(cartId);
    }
  }, 700),
  [cartId]
);

// При изменении адреса
useEffect(() => {
  debouncedCalculateShipping(address);
  return () => {
    debouncedCalculateShipping.cancel();
  };
}, [address.postcode, address.city, address.address_1, address.country]);
```

### Важные примечания:

- **Задержка**: 500-800 мс оптимальна для баланса между отзывчивостью и количеством запросов
- **Отмена**: При новом изменении адреса предыдущий запрос должен отменяться
- **Проверка заполненности**: Не вызывать API, если адрес не заполнен полностью
- **Очистка**: Отменять pending запросы при размонтировании компонента

## GraphQL запросы и mutations

### Query: Получение корзины

```graphql
query GetCart($cartId: ID!) {
  cart(cartId: $cartId) {
    cartId
    shippingAddress {
      fullName
      postcode
      city
      address1
      country
      province
    }
    shippingMethod
    shippingFee {
      value
      text
    }
    grandTotal {
      value
      text
    }
    items {
      productId
      productName
      qty
      productWeight
    }
  }
}
```

### Mutation: Расчет доставки

```graphql
mutation CalculateShipping($cartId: ID!) {
  calculateShipping(cartId: $cartId) {
    provider
    providerName
    options {
      id
      name
      price
      currency
      estimatedDays
      serviceCode
      provider
    }
    error
  }
}
```

### Mutation: Сохранение выбранного метода

```graphql
mutation UpdateShippingMethod($cartId: ID!, $shippingMethod: JSON!) {
  updateCartShippingMethod(cartId: $cartId, shippingMethod: $shippingMethod) {
    cart {
      shippingMethod
      shippingFee {
        value
        text
      }
      grandTotal {
        value
        text
      }
    }
  }
}
```

**Формат shippingMethod**:
```json
{
  "method_id": "123",
  "provider": "postnord",
  "option_id": "delivery_option_id_from_postnord",
  "price": 199,
  "metadata": {
    "deliveryOptionId": "delivery_option_id_from_postnord",
    "serviceCode": "SERVICE_123",
    "estimatedDays": 5
  }
}
```

## Обработка edge cases

### 1. Изменение адреса после выбора варианта

**Логика**:
- При изменении адреса сбрасывать выбранный вариант
- Показывать сообщение: "Адрес изменен, пожалуйста, выберите вариант доставки заново"
- Автоматически пересчитывать варианты для нового адреса

### 2. Изменение состава корзины

**Логика**:
- При добавлении/удалении товаров пересчитывать варианты доставки
- Использовать debounce для пересчета
- Если выбранный вариант стал недоступен - сбросить выбор

### 3. Таймаут запроса

**Логика**:
- Установить таймаут для GraphQL запроса (например, 15 секунд)
- При таймауте показывать сообщение об ошибке
- Предложить повторить запрос

### 4. Пустая корзина

**Логика**:
- Не показывать блок выбора доставки, если корзина пуста
- Показывать сообщение: "Добавьте товары в корзину для расчета доставки"
